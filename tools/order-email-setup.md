# 주문 알림 메일 연결

구현 상태: 주문 접수 시 두 수신자에게 알림을 보내는 코드와 발송 결과 기록 준비 완료. 실제 발송에는 아래 설정이 필요합니다.

## 수신자
- 대표: buf28@naver.com
- 담당: annova@naver.com

네이버 수신 계정의 비밀번호나 SMTP 승인은 필요하지 않습니다. 발신은 사이트 전용 발송 서비스를 이용합니다.

## 기존 Gmail SMTP 연결 (우선 사용)
기존 arttelling-shop 프로젝트의 Gmail SMTP 인증은 2026-09-29 정상 확인했습니다. 비밀번호는 이 문서에 기록하지 않습니다.
- 운영 서버의 `SMTP_USER`에 기존 발신 계정, `SMTP_PASS`에 해당 앱 비밀번호를 등록합니다.
- 두 값이 있으면 Gmail SMTP를 우선 사용하므로 Resend 키와 도메인 인증이 필요하지 않습니다.
- 네이버 수신자는 그대로 유지합니다.
- SMTP에는 발송 중복 방지 API가 없으므로 응답 불명확·부분 수신 건은 ‘발송 이력 확인 필요’로 남깁니다. 보낸메일함 확인 없이 자동 재발송하지 않습니다.

## Resend 연결 (대체 방식)
1. Resend에서 사이트 소유 도메인(예: mail.artell.co.kr)을 등록하고 안내되는 DNS 레코드로 발신 도메인을 인증합니다.
2. 해당 도메인 발송 권한 API 키를 만들고 Vercel 운영 환경의 `RESEND_API_KEY`에 입력합니다. 채팅이나 Git에 키를 올리지 않습니다.
3. 인증된 도메인의 발신 주소를 `ORDER_EMAIL_FROM`에 입력합니다. 예: `Goodsflap <orders@mail.artell.co.kr>`.
4. `ORDER_EMAIL_TO`는 `buf28@naver.com,annova@naver.com`으로 설정합니다. 생략 시에도 이 두 주소를 사용합니다.
5. 재배포 후 관리자 → 주문 관리에서 '연결됨'을 확인하고, 명확하게 시연 주문으로 표시한 주문으로 두 주소 수신 여부를 확인합니다. 발송 서비스 접수 성공은 받은편지함 도착 보장이 아니므로 스팸함도 확인합니다.

## 동작
- 장바구니 저장만으로는 알림을 보내지 않습니다. 서버에 주문이 생성된 후 접수 알림을 보냅니다.
- 결제 대기 / 시연 주문을 명확하게 표시합니다. 결제 완료 여부는 관리자 화면에서 확인합니다.
- 원본 이미지와 배송 주소는 메일에 첨부하지 않습니다. 관리자 로그인 후 확인합니다.
- 발송 서비스가 연결되지 않아도 주문 접수는 유지됩니다. 알림은 대기 상태로 보관됩니다.
- 실패한 알림은 관리자 주문 관리에서 재시도할 수 있습니다. 자동 주기 재시도는 아직 설정하지 않았습니다.
- 발송 성공은 다시 보내지 않습니다. 최초 시도 후 23시간을 넘긴 미확인 건은 서비스 로그를 확인하기 전 다시 보내지 않습니다.
- 발송 전에 연결되지 않은 기존 주문은 자동으로 일괄 발송하지 않습니다. 관리자에서 필요한 주문만 발송합니다.
