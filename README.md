# 아트텔링 굿즈 스튜디오

5종 상품을 위한 로컬 실행 MVP입니다. [구축 계획](docs/MVP-PLAN.md)에 정보구조, 화면, 데이터 모델, 기술 선택, 개발 우선순위, 도메인 전환 절차를 정리했습니다.

## 실행
Node.js 24 이상에서 이 폴더를 열고 `npm install`, `npm start`를 실행합니다. http://localhost:4310 에서 확인합니다. 초기에는 시연 주문 모드입니다. 실제 결제·제작·배송은 일어나지 않습니다. 서버는 로컬 주소에만 바인딩합니다.

`.env.example`을 `.env`로 복사하고 `ADMIN_TOKEN`을 긴 임의 값으로 설정합니다. 미설정 시 실행할 때 임시 관리자 키가 터미널에 표시됩니다. 하단 ‘제작 관리’에서 입력하면 주문·상태·파일을 관리합니다. 관리자 키는 브라우저 메모리에만 보관됩니다.

## 사용
상품 선택 → 옵션 → PNG/JPG/WebP 업로드 → 드래그/슬라이더로 배치 → 미리보기 → 수량 → 장바구니 → 배송 정보와 시안 확인 → 시연 주문. 이후 내 주문과 제작 관리에서 상태를 확인합니다. 장바구니는 브라우저, 주문과 파일은 서버 data 폴더에 저장됩니다. data 폴더는 공개 정적 파일로 제공하지 않습니다.

## 결제 연결
토스페이먼츠 결제창 v2를 사용합니다. API 개별 연동의 결제창(구버전)용 클라이언트·시크릿 키를 `.env`의 TOSS_CLIENT_KEY / TOSS_SECRET_KEY에 넣습니다. 위젯용 키와 혼용하지 않습니다. PUBLIC_URL은 사용자가 접속하는 주소와 일치해야 합니다. 현재 결제 수단은 카드입니다. 브라우저는 서버가 확정한 금액으로 결제를 요청하고, 성공 콜백 이후 서버가 금액·주문 소유권을 검증하고 승인 API를 호출합니다. 주문 ID를 멱등 키로 사용합니다. 결제 실패/취소 후 주문 조회에서 재시도합니다.

실제 토스 계정 키가 제공되지 않아 결제창·실승인은 검증하지 않았습니다. 운영 전에 테스트 키 승인, 실패, 중복, 네트워크 중단과 복구, 웹훅·대사를 추가 검증해야 합니다. 세션 쿠키가 유지되는 같은 브라우저에서 돌아와야 합니다.

## 파일과 제품 제한
단일 이미지/단면 MVP입니다. normalized PNG는 편집용이고, 원본 다운로드는 업로드 바이트를 그대로 유지합니다. 출력은 서버에서 원본과 변환 값을 합성한 300 DPI PNG입니다. 상품의 mm 규격은 임시이며 모든 출력은 REVIEW 표시가 있습니다. 자동 칼선, CMYK 프로파일, 화이트 잉크판, 도련, 실사 곡면 목업은 아직 지원하지 않습니다. 제작사와 규격을 확정하고 샘플 검증을 거쳐야 합니다.

## 검증
`npm test`: 가격·옵션·수량 검증, 업로드, 세션 격리, 관리자 보호, 시연 주문, 상태 전환, 원본 보존, 출력 픽셀·DPI 확인. 테스트는 3017 포트를 사용합니다.

## Vercel + Supabase 배포
Vercel 프로젝트는 이 GitHub 저장소의 루트 디렉터리를 연결합니다. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_TOKEN`을 Vercel 환경변수로 설정합니다. `PUBLIC_URL`은 전용 도메인을 연결할 때 `https://artell.co.kr`로 추가합니다. 시크릿 키와 관리자 키는 GitHub 또는 브라우저 코드에 넣지 않습니다. Supabase를 설정하지 않은 로컬 실행은 기존 SQLite `data` 폴더를 계속 사용합니다.

## 출시 전 남은 작업
계정 인증·주문 복구, 상품 단가·옵션 확정, 개인정보·약관·맞춤제작 동의, 토스 계약/테스트, 결제 대사/환불, 배송 연동, 업로드 수명과 삭제 정책, 속도 제한, 백업·관측, 운영 저장소, HTTPS 배포. 현재 프로젝트는 로컬 검증 단계이며 공개 판매 서비스로 배포하지 않았습니다. 도메인·AWS·가비아·메일 DNS는 변경하지 않았습니다.
