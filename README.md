# 아트텔링 굿즈 스튜디오

12종 상품을 위한 로컬 실행 MVP입니다. [구축 계획](docs/MVP-PLAN.md)에 정보구조, 화면, 데이터 모델, 기술 선택, 개발 우선순위, 도메인 전환 절차를 정리했습니다.

## 실행
Node.js 24 이상에서 이 폴더를 열고 `npm install`, `npm start`를 실행합니다. http://localhost:4310 에서 확인합니다. 초기에는 시연 주문 모드입니다. 실제 결제·제작·배송은 일어나지 않습니다. 서버는 로컬 주소에만 바인딩합니다.

`.env.example`을 `.env`로 복사합니다. 로컬에서는 SQLite `data` 폴더로 동작하고, 회원가입·로그인도 바로 확인할 수 있습니다. 운영에서는 `ADMIN_TOKEN`을 긴 임의 값으로 반드시 설정해야 합니다.

## 사용
상단 로그인 메뉴에서 회원가입·로그인하고 `내 계정`, `내 주문`을 이용합니다. 상품 선택 → 옵션 → PNG/JPG/WebP 업로드 → 드래그/슬라이더로 배치 → 미리보기 → 수량 → 장바구니 → 배송 정보와 시안 확인 → 시연 주문 순서로 진행합니다. 주문과 업로드 파일은 로그인 계정에 연결되며, 다른 계정은 볼 수 없습니다. 장바구니는 현재 로그인 계정별로 이 브라우저에만 저장됩니다.

운영자 계정은 회원가입 또는 로그인 후 `/#admin`에서 최초 한 번만 `ADMIN_TOKEN`을 입력해 연결합니다. 첫 활성 관리자가 만들어진 뒤에는 관리자 화면의 회원 관리에서만 다른 관리자 권한을 부여할 수 있습니다. 관리자는 주문 상태·제작 파일, 회원 역할·이용 상태, 상품 정보·가격·옵션·공개 여부를 관리합니다.

## 결제 연결
토스페이먼츠 결제창형 v2를 사용합니다. 결제창형 연동 키(`gck`/`gsk`) 한 쌍을 `.env`의 TOSS_CLIENT_KEY / TOSS_SECRET_KEY에 넣습니다. 사이트는 최신 결제위젯 방식으로 결제수단과 약관 UI를 표시합니다. PUBLIC_URL은 사용자가 접속하는 주소와 일치해야 합니다. 현재 결제 수단은 카드입니다. 브라우저는 서버가 확정한 금액으로 결제를 요청하고, 성공 콜백 이후 서버가 금액·주문 소유권을 검증하고 승인 API를 호출합니다. 주문 ID를 멱등 키로 사용합니다. 결제 실패/취소 후 주문 조회에서 재시도합니다.

실제 토스 계정 키가 제공되지 않아 결제창·실승인은 검증하지 않았습니다. 운영 전에 테스트 키 승인, 실패, 중복, 네트워크 중단과 복구, 웹훅·대사를 추가 검증해야 합니다. 세션 쿠키가 유지되는 같은 브라우저에서 돌아와야 합니다.

## 파일과 제품 제한
단일 이미지/단면 MVP입니다. normalized PNG는 편집용이고, 원본 다운로드는 업로드 바이트를 그대로 유지합니다. 출력은 서버에서 원본과 변환 값을 합성한 300 DPI PNG입니다. 상품의 mm 규격은 임시이며 모든 출력은 REVIEW 표시가 있습니다. 자동 칼선, CMYK 프로파일, 화이트 잉크판, 도련, 실사 곡면 목업은 아직 지원하지 않습니다. 제작사와 규격을 확정하고 샘플 검증을 거쳐야 합니다.

## 검증
`npm test`: 가격·옵션·수량 검증, 회원 로그인, 계정별 파일·주문 격리, 최초 관리자 연결, 상품 관리, 시연 주문, 상태 전환, 원본 보존, 출력 픽셀·DPI를 확인합니다. 테스트는 3017 포트를 사용합니다.

## Vercel + Supabase 배포
Vercel 프로젝트는 이 GitHub 저장소의 루트 디렉터리를 연결합니다. 배포 전에 `supabase/migrations/20260914082948_members_admin_products.sql`을 Supabase SQL Editor 또는 CLI로 적용합니다.

Vercel에는 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `PUBLIC_URL`, `ADMIN_TOKEN`을 설정합니다. `PUBLIC_URL`은 실제 주소(예: `https://artell.co.kr`)여야 합니다. Supabase Authentication의 URL Configuration에도 같은 Site URL과 `https://artell.co.kr/?confirmed=1` Redirect URL을 추가하고, 이메일 확인을 켭니다. 가입자는 인증 메일의 링크를 누른 뒤 로그인 세션이 열립니다.

시크릿 키와 관리자 키는 GitHub 또는 브라우저 코드에 넣지 않습니다. Supabase를 설정하지 않은 로컬 실행은 기존 SQLite `data` 폴더를 계속 사용합니다.

## 출시 전 남은 작업
상품 단가·옵션 확정, 개인정보·약관·맞춤제작 동의, 비밀번호 재설정, 토스 계약/테스트, 결제 대사/환불, 배송 연동, 업로드 수명과 삭제 정책, 백업·관측을 준비해야 합니다. 현재 프로젝트는 로컬 검증 단계이며 공개 판매 서비스로 배포하지 않았습니다. 도메인·AWS·가비아·메일 DNS는 변경하지 않았습니다.
